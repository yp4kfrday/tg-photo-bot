---

## 🎯 Какую проблему решает бот?

В Telegram неудобно выгружать фотографии пачками:
- Приходится сохранять каждый снимок по отдельности.
- При пересылке множества фото чат превращается в бесконечную ленту.
- Если фото нужно распечатать (чеки, акты, документы, фотоотчёты с объектов или мероприятий), приходится вручную компоновать их на листах в редакторе.

**tg-photo-bot** решает эту проблему: вы просто пересылаете или загружаете пачку фото, а бот автоматически собирает их в единый файл без лишних кнопок и подтверждений.

## ⚡ Как это работает

```
 Пользователь                   Бот (Debounce Queue)                 Результат
┌────────────┐                 ┌────────────────────┐              ┌───────────────┐
│ 📷 Фото 1  │ ──────────────> │                    │              │ 📦 photos.zip  │
│ 📷 Фото 2  │ ──────────────> │ Таймер 4 сек       │ ───────────> │     или       │
│ 📷 Фото N  │ ──────────────> │ (сброс при каждом) │              │ 📄 photos.pdf  │
└────────────┘                 └────────────────────┘              └───────────────┘
```

1. **Выберите режим:**
   - `/zip` — упаковка исходных фото в ZIP-архив (по умолчанию).
   - `/pdf` — верстка плотного A4 PDF-коллажа.
2. **Отправьте фотографии:** можно слать альбомами, по одной или пачкой в несколько приёмов.
3. **Получите результат:** бот выдерживает паузу в 4 секунды после последней полученной фотографии и присылает готовый файл. Нажимать «Готово» не требуется!

## 🛠 Под капотом и архитектура

Проект написан на Go с упором на надежность, предсказуемость и безопасность:

- **In-Memory Debounce Queue:**
  Telegram API присылает фотографии из медиагруппы не единым пакетом, а отдельными апдейтами. Бот объединяет их через потокобезопасную очередь (`sync.RWMutex` + `time.AfterFunc`), обновляя таймер при каждом новом входящем файле.
- **Генератор A4 PDF-коллажей (сетка 4×5):**
  - До 20 фотографий на страницу A4 с автоматической разбивкой на новые страницы при превышении лимита.
  - Центрированный автокроп (`imaging.Fill` с ресемплингом Lanczos) — ячейки заполняются полностью без искажения пропорций и белых полей.
  - Печатное разрешение 150 DPI — баланс между четкостью при распечатке и легким весом PDF-документа.
- **Защита от перегрузки (Rate Limiting & DoS):**
  - Лимит пачки: максимум 100 фотографий на одну очередь пользователя.
  - Семафор загрузки: скачивание ограничено пулом из 8 параллельных потоков, что защищает от ошибок `429 Too Many Requests` и блокировок со стороны Telegram Bot API.
  - Защита от Path Traversal при формировании ZIP: имена файлов санитизируются до базовых.
- **Изоляция и гарантированная очистка:**
  Каждый батч обрабатывается в индивидуальной временной папке `os.MkdirTemp`. Конструкция `defer os.RemoveAll` очищает диск даже в случае непредвиденных сбоев или panic.
- **Честный Graceful Shutdown:**
  При получении сигналов `SIGINT`/`SIGTERM` бот мгновенно прекращает принимать новые сообщения, но основной поток ожидает завершения всех запущенных загрузок и генераций перед выходом.

## 📂 Структура проекта

```
tg-photo-bot/
├── main.go                     # Точка входа: инициализация, graceful shutdown
├── bot/
│   ├── bot.go                 # Инициализация Telebot, маршрутизация хэндлеров
│   ├── handlers.go            # Обработчики команд (/start, /zip, /pdf) и фото
│   └── queue.go               # In-memory per-user очередь с debounce-таймером
├── processor/
│   ├── processor.go           # Пайплайн: скачивание → генерация → отправка → очистка
│   ├── downloader.go          # Параллельное скачивание с пулом воркеров
│   ├── archiver.go            # Упаковка файлов в ZIP
│   ├── pdfgen.go              # Генератор PDF-коллажа (fpdf + imaging)
│   └── pdfgen_test.go         # Unit-тесты архиватора и PDF-модуля
├── deploy/
│   ├── tg-photo-bot.service   # Hardened systemd unit
│   └── deploy.sh              # Скрипт автоматического деплоя на сервер
├── bootstrap.sh               # Скрипт быстрой проверки зависимостей и тестов
├── .env.example               # Шаблон конфигурации
└── .gitignore                 # Исключение токенов, бинарников и временных файлов
```

## 🚀 Быстрый старт

### Требования
- Go 1.21+
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)

### Установка и запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/<ваш-username>/tg-photo-bot.git
   cd tg-photo-bot
   ```

2. **Настройте переменные окружения:**
   ```bash
   cp .env.example .env
   ```
   Откройте `.env` и вставьте ваш токен:
   ```env
   BOT_TOKEN=your_bot_token_here
   ```

3. **Запустите тесты:**
   ```bash
   go test -v ./processor/...
   ```

4. **Запустите бота:**
   ```bash
   go run .
   ```

## 🌐 Деплой на VPS (Ubuntu / Debian)

В каталоге `deploy/` подготовлен скрипт развертывания и systemd unit с усиленной изоляцией:

### 1. Сборка бинарника под Linux
```bash
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-s -w" -o tg-photo-bot .
```

### 2. Запуск деплоя на сервере
Скрипт `deploy/deploy.sh` автоматически:
- Создает системного пользователя `tgbot` без домашней директории и шелла;
- Размещает бинарник в `/opt/tg-photo-bot`;
- Настраивает права доступа и устанавливает systemd service;
- Запускает сервис с автозагрузкой.

```bash
# Запуск от root или через sudo на сервере
sudo bash deploy/deploy.sh
```

### Особенности безопасности сервиса:
- `PrivateTmp=true` — изолированный временный каталог `/tmp`;
- `ProtectSystem=strict` и `ProtectHome=true` — файловая система только для чтения (запись разрешена исключительно во временный `/tmp`);
- `NoNewPrivileges=true` — запрет на повышение привилегий процесса.
